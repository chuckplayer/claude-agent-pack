Rationale: `/implement`'s pipeline has three points where a human decides what happens next (git-engineer's `AskUserQuestion` gates, finding adjudication, retry routing), and workflow subagents can't prompt the user — a script could only wrap the fan-out stage, leaving the prose rules necessary anyway for everything around it. The pack's fan-outs are also single digits wide, well under both the concurrent-subagent cap (20) and the workflow size guideline (15), so there's no scale problem the engine would solve. **Reopen condition, stated explicitly:** a Claude Code release that lets a workflow script pause for user input. Until then, this review should cite the decision file rather than re-deriving the recommendation. One candidate was left genuinely open for a future revisit if reopened: workflow-ifying just the reviewer fan-out in `/review-pr` (no interactive gates there) — noted but not adopted now, since it would add a second orchestration idiom for a fan-out that already runs in parallel today.

3. **Background-agent auto-publish vs. merge-reviewer/git-engineer gate (open since 2026-07-22, GitHub #73197).** The upstream bug is *not* fixed — confirmed via changelog re-scan, #73197 still open with no opt-out through 2.1.220 — but the pack now documents and mitigates it properly: new `memory/known-issues/2026-07-27-background-agent-auto-publish-bypasses-merge-gate.md`, plus a one-line "**Never publish**" hard constraint added to all six engineer agents (csharp-, frontend-, mcp-, database-, python-, infrastructure-engineer), instructing them to decline any auto-commit/auto-push/draft-PR offer and report it in the handoff summary instead.
